REPO CANVAS 0.7.0 — УСТАНОВКА В СУЩЕСТВУЮЩИЙ ПРОЕКТ

Ты устанавливаешь локальную смысловую карту проекта с отдельными Architect и Observer. Выполни сценарий самостоятельно. Не анализируй архитектуру проекта вместо Architect и не меняй продуктовый код.

Источник установки выбирается автоматически по тому, что дал владелец:

- если владелец дал только ссылку `https://github.com/m0ast-git/repo-canvas`, используй закреплённый GitHub release `github:m0ast-git/repo-canvas#v0.7.0`;
- если в корне проекта уже лежит `repo-canvas-0.7.0.tgz`, используй локальный архив и не обращайся к сети.

1. Прочитай корневые инструкции проекта и проверь `git status`. Сохрани пользовательские и чужие изменения.

2. Проверь Node.js 22+, npm и Git. Если чего-то нет, не устанавливай системные компоненты сам: сообщи владельцу точный недостающий компонент.

3. Из корня проекта выбери ровно одну команду установки.

   Если дан только GitHub-репозиторий:

   npm install --save-dev --save-exact --ignore-scripts github:m0ast-git/repo-canvas#v0.7.0

   Если рядом лежит локальный архив:

   npm install --save-dev --save-exact --ignore-scripts ./repo-canvas-0.7.0.tgz

   После успешной установки выполни:

   npx --no-install repo-canvas setup

   `setup` сам:
   - безопасно обновит пакетные scripts и локальные служебные файлы;
   - удалит старые Repo Canvas hooks/блоки из AGENTS.md, сохранив инструкции владельца;
   - проверит существующую локальную Codex-подписку;
   - запустит headless Architect на `gpt-5.6-sol`, reasoning medium;
   - построит полную смысловую карту без лимита сущностей;
   - включит репозиторный Observer на `gpt-5.4-mini`;
   - автоматически подключит публичные локальные журналы Codex, Claude Code и Kimi Code, если они присутствуют.

   Если `package.json` отсутствовал, npm создаст минимальный служебный manifest. Не запускай `npm init` и не выдумывай метаданные продукта. При конфликте остановись, ничего не перетирая.

4. Запусти ровно один foreground-сервер в устойчивом терминале:

   npm run repo-canvas:start

   Используй существующий здоровый сервер этого проекта, если он уже работает. Не убивай посторонние процессы. Если 4173 занят, выбери свободный порт:

   npm run repo-canvas -- start --port <port>

5. Дождись строки `Repo Canvas listening at ...`, открой выданную локальную ссылку и проверь глазами:
   - области и сущности читаемы;
   - связи не перекрывают карточки;
   - нет горизонтального скролла страницы;
   - provisional/active работа заметна;
   - перетаскивание областей и нод работает.

6. Выполни:

   npm run repo-canvas -- check
   npm run repo-canvas -- observer status

7. Сообщи владельцу локальную ссылку, число областей/сущностей/связей, результат check и единственный реальный блокер, если он остался.

После установки обычные рабочие агенты ничего не публикуют в Canvas и не получают Canvas-инструкции. Observer читает публичные журналы Codex, Claude Code и Kimi Code только для этого репозитория. При старте новой задачи он немедленно показывает черновую карточку, затем уточняет её по публичным событиям сессии. Claude `thinking`, Kimi `think`, tool results и скрытый reasoning игнорируются; репозиторий повторно не сканируется.

Перестроение после крупной архитектурной смены или по запросу владельца:

   npm run repo-canvas -- architect --refresh

Для остановки наблюдения:

   npm run repo-canvas -- observer disable

Для повторного включения:

   npm run repo-canvas -- observer enable
