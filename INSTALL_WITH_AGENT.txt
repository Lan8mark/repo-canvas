REPO CANVAS — УСТАНОВКА В СУЩЕСТВУЮЩИЙ ПРОЕКТ

Твоя задача: установить Repo Canvas в текущий репозиторий, построить смысловую карту, запустить локальный сервер и вернуть владельцу рабочую ссылку.

Границы работы:
- сохрани пользовательские и чужие изменения;
- не меняй продуктовый код;
- не добавляй инструкции, skills или hooks рабочим агентам;
- не устанавливай системные компоненты без разрешения владельца.

1. Из корня проекта прочитай его инструкции и проверь `git status`.

2. Проверь Node.js 22+, npm и Git. Если компонента не хватает, сообщи владельцу его точное название и остановись.

3. Выбери один источник установки.

   Если владелец дал ссылку на GitHub:

   npx --yes --package=github:Lan8mark/repo-canvas#v0.10.0 repo-canvas bootstrap

   Если в корне проекта лежит `repo-canvas-0.10.0.tgz`:

   npx --yes --package=./repo-canvas-0.10.0.tgz repo-canvas bootstrap

   `bootstrap` установит весь постоянный runtime и зависимости внутрь `.repo-canvas/`, проверит локальное подключение Codex, запустит read-only Architect на `gpt-5.6-sol` с reasoning medium, построит смысловую карту и включит Observer на `gpt-5.4-mini`. Observer будет следить за публичными локальными журналами Codex, Claude Code и Kimi Code, относящимися к этому репозиторию.

   Единственный постоянный след в проекте — самоигнорируемая папка `.repo-canvas/`. Не меняй `package.json`, lock-файлы, корневой `.gitignore`, `node_modules`, инструкции или hooks проекта. После установки проверь `git status`: он должен совпадать с состоянием до установки. При конфликте остановись, ничего не перетирая.

4. Запусти один foreground-сервер в устойчивом терминале:

   node .repo-canvas/repo-canvas.mjs start

   Если сервер Repo Canvas для этого проекта уже работает, используй его. Не завершай посторонние процессы. Если порт 4173 занят, выбери свободный:

   node .repo-canvas/repo-canvas.mjs start --port <port>

5. Дождись строки `Repo Canvas listening at ...`: сервер сам откроет защищённую карту в браузере. Проверь фактическое отображение; остальные вкладки на этом локальном адресе подключатся автоматически. Если браузер не открылся, открой точную напечатанную ссылку вместе с `#token=...`:
   - в слое `Смысл` каждая сущность объясняет проблему и решение простым языком;
   - в слое `Техника` видны механизм, гарантия и путь к реализации;
   - заголовки и тела карточек показаны полностью, без `...`;
   - рубленые связи и их подписи не перекрывают карточки;
   - страница не имеет горизонтального скролла;
   - активная и черновая работа хорошо заметна;
   - раскладка заблокирована по умолчанию и разблокируется кнопкой `Позиции`;
   - двойной клик по названию области, ноды или связи открывает ручное переименование.

6. Выполни:

   node .repo-canvas/repo-canvas.mjs check
   node .repo-canvas/repo-canvas.mjs observer status

7. Верни владельцу:
   - локальную ссылку;
   - число областей, сущностей и связей;
   - результат `check`;
   - единственный реальный блокер, если он остался.

После этой установки терминал для будущих обновлений не нужен. Когда выйдет новый проверенный релиз, внизу Canvas появится кнопка `Update`; она установит новую версию в ignored-каталог, перезапустит сервер и сохранит текущую карту.

После запуска сервера Observer создаёт черновую карточку при первом событии новой работы и затем уточняет её по публичным событиям сессии. Обычным рабочим агентам Canvas-инструкции не нужны. Claude `thinking`, Kimi `think`, tool results и скрытый reasoning игнорируются. Во время наблюдения Observer не сканирует файлы проекта заново.

После крупной перестройки проекта или по запросу владельца обнови смысловую карту:

   node .repo-canvas/repo-canvas.mjs architect --refresh

Остановить наблюдение:

   node .repo-canvas/repo-canvas.mjs observer disable

Включить его снова:

   node .repo-canvas/repo-canvas.mjs observer enable
